Step 4: Numerical Feature Discretization/Encoding.

Transforms stable numerical features into a discrete encoded space 
based on the selected fitting strategy.

#### Parameters

**`inputs`** : *`NumEncoderInput`*
<div style={{"paddingLeft": "1.25rem", "marginTop": "0.25rem", "marginBottom": "1rem"}}>Custom encoding configuration. If None, resolves from 'train.stable' and        'features.num.stable.dist'.</div>

**`**kwargs`** : *`dict`*
<div style={{"paddingLeft": "1.25rem", "marginTop": "0.25rem", "marginBottom": "1rem"}}>Additional parameters passed to the NumEncoder worker.</div>

#### Examples

Defining the Project Context (Control Plane) & Project Scope:

```python
import aidflow as aid

ctx = aid.ProjectContext()

ctx.genesis(
    project      = 'test',
    input_data   = 'test.csv',
    target       = 'target',
    yy_mm        = 'decision_date',
    yy_mm_format = '%Y-%m-%d'
)
ctx.params()
```

### Worker → Model → Fitter
Accessing worker's inputs schema → parameters & types (*shown in the display output*):

```python
ctx.workers.num_encoder.spec
```

Accessing model's fitter options and schema → parameters & types
(*shown in the display output*):

```python
ctx.workers.num_encoder.fitters
```

Executing workers with defaults → auto provided by the context:

```python
ctx.workers.data_loader()    # 0. import data to the context scope
ctx.workers.fe_cleaner()     # 1. apply cleaning logic to the imported data (0)
ctx.workers.fe_stabilizer()  # 2. apply temporal stability logic to the cleaned data (1)
ctx.workers.obs_stabilizer() # 3. apply observation stability logic to the cleaned data (2)
ctx.workers.num_encoder()    # 4. apply numerical encoding logic to the stable data (3)
```

Note that steps 0-3 can be run by ExecutionContext one-liner:

```python
ctx.flow.process('data', verbose = 0) # steps 0 - 3 have been trained within the context scope
```

Once worker has been executed, thus its main model has been built,    we have access to all populated attributes.

```python
worker   = ctx.workers.num_encoder
inputs   = worker.spec.inputs
result   = worker.result
state    = worker.state
features = worker.features
params   = worker.params
stats    = worker.stats
fitter   = worker.fitter  # jump to chosen internal fitter
...
```

View to model report of executed worker:

```python
ctx.workers.num_encoder.report.show()
```

### Model → Fitter
Once worker has been executed, we can obtain internal fitter state    and its parametrization (*shown in the display output*):

```python
ctx.workers.num_encoder.fitter
```

The fitted fitter provides all populated attributes.

```python
fitter    = ctx.workers.num_encoder.fitter
result_   = fitter.result
features_ = fitter.features
params_   = fitter.params
stats_    = fitter.stats
```

Direct choice and parametrization of internal fitter:

```python
fx  = ctx.workers.num_encoder.fitters[0]
prm = dict(
    max_num_bins  = 20,
    min_bin_share = 0.05,
    gini_cutoff   = 0.01 
)
num_encoder = ctx.workers.num_encoder(fx_choice = fx, fx_params = prm)
```

In the experimenting phase, when various parametrization settings might be under testing    (*note that internal fitter API (fx_config) can vary with respect to chosen fitter*):

```python
cfg = dict(
    target   = 'target2',
    discrete = 15
)
num_encoder = ctx.workers.num_encoder(fx_config = cfg)
```

#### Attributes

<Info>
  All worker attributes return `None` prior its execution.
</Info>
| Attribute | Type | Description |
| :--- | :--- | :--- |
| `inputs` | `ModelInput` | Registered populated inputs containing execution timestamps and feature definitions. |
| `result` | `ModelResult` | Execution output payload containing model predictions and fit results. |
| `fitter` | `Fitter` | Underlying fitted estimator instance. |
| `state` | `ModelState` | Consolidated model state (fitter, choice, params, features, report, stats). |
| `report` | `DashboardInterface` | Interactive report interface. Call `report.show()` to render the visualization dashboard. |
| `stats` | `FitStats` | Performance metrics and training metadata gathered during fitting. |
| `features` | `TransResCols` | Feature schema dataclass required for downstream inference. |
| `params` | `tuple[FitParams, Parameters, ...]` | Tuple of fit settings, execution parameters, optionally transformer parameters. |
| `choice` | `RegGet.Choice` | Active configuration parameters including internal fitter choice (`fx_choice`). |
| `model_signature` | `str` | Unique hash identifier for the fitted model instance. |
